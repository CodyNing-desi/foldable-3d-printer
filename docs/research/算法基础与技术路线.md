# 折叠打印机的算法基础与技术路线

## 一、先给路线判断

| 机械路线 | 展开后的运动学 | 算法新增工作 | 当前适配性 |
|---|---|---|---|
| 铰链折下龙门／Z 柱 | 仍是原来的 Cartesian／CoreXY 等线性轴 | 主要是展开状态确认、回零、校准与安全联锁 | **最适合作为第一版** |
| 伸缩导轨＋铰链收纳 | 展开并锁定后仍是线性轴 | 伸缩位置、锁定状态、回零和附件避让 | 可优先考虑，但机构需先成立 |
| 快拆后平放 | 重新装配后仍是线性轴 | 重新回零、调平和连接检查 | 算法少，但用户操作和磨损成本高 |
| 剪刀升降 Z 轴 | 电机位移与喷嘴高度通常不是固定比例 | 非线性映射、可变速度／力、回差、左右同步、回零和专用测试 | 高风险研究路线 |
| 机械臂／五轴 | 工具位姿与关节角之间需要正逆运动学 | 逆运动学、姿态、碰撞、非平面切片和 G-code 生成 | 后续独立路线，不与折叠首版合并 |

**核心判断：如果第一版目标是“折叠后恢复打印”，优先保留展开后的线性运动学。选择剪刀轴不是只换一种机构，而是同时选择一套新的运动控制问题。**

## 二、剪刀 Z 轴为什么不能只改 `steps/mm`

以理想单级剪刀机构为简化模型：

- 杆长为 `L`；
- 杆与水平面的夹角为 `θ`；
- 平台高度为 `H`；
- 两个水平端点之间的距离为 `S`。

理想几何关系为：

```text
H = 2L sin(θ)
S = 2L cos(θ)
H² + S² = 4L²
```

因此：

```text
H = √(4L² − S²)
S = √(4L² − H²)
```

并且：

```text
dH/dS = −S/H
```

这意味着同一个水平驱动位移，在不同高度对应的垂直位移不同。接近折平位置时，`H` 很小，几何增益和所需驱动力会显著变化。真实机构还有偏置、铰点位置、多级剪刀、导轨摩擦和弹性变形，必须按实际 CAD 重新建模，不能直接套公式。

这也解释了已有原型记录中的问题：

- FoldaRapX 需要非线性 Z 补偿，未补偿时 50 mm 测试立方体被打成 50×50×80 mm，并记录低位扭矩、跳齿和间隙问题。[FoldaRapX](https://reprap.org/wiki/FoldaRapX)
- X printer V1 在 Marlin 中加入非线性关系，后续仍记录回差、回零漂移和结构变形。[X printer](https://hackaday.io/project/165889-x-printer-portable)
- 2014 年 RepRap 讨论已经尝试把剪刀公式放入 Marlin 的 `planner.cpp`，但帖子中的代码只是未验证的粗略尝试，不能当作可复用驱动。[RepRap 讨论](https://reprap.org/forum/read.php?147,314344)
- Marlin 的后续议题也说明非线性剪刀 Z 轴不是常规配置项。[Marlin issue #11680](https://github.com/MarlinFirmware/Marlin/issues/11680)

## 三、固件与代码应该看什么

### 1. X printer：真实机器的非线性 Z 实现

上游：`alpha3141/X_printer`，快照目录 `external/x-printer/`。

当前仓库实际只包含 CAD、图片、README 和许可证，**没有公开非线性 Z 的固件源码**。因此目前只能保存 CAD，并从项目日志了解“作者曾修改公式”的说法；不能写成代码已经开源可复用。

后续若取得代码，再核对：

- 非线性 Z 公式实际写入哪个文件；
- 输入是丝杆位移、电机步数还是其他中间量；
- 回零开关安装在哪个基准件上；
- V1 日志中的回差和回零问题是否真由代码解决。

### 2. Foldup：剪刀折叠机的 Klipper 配置起点

上游：`KaiPereira/Foldup-3D-Printer`，快照目录 `external/foldup/`。

README 提供 Marlin／Klipper 路线和 firmware 目录，并明确称其中内容为 boilerplate。本次对快照的检索未发现剪刀专用运动学实现；`SCISSOR_XY` 等命中来自 Marlin 的显示屏图形裁剪 API，与剪刀升降无关。**普通 Klipper 配置或 Marlin 源码树不等于剪刀运动学已经实现。**[Foldup 项目](https://github.com/KaiPereira/Foldup-3D-Printer)

### 3. Klipper：自定义运动学的正式入口

上游：`Klipper3d/klipper`，快照目录 `external/klipper/`。

[Klipper Code Overview](https://www.klipper3d.org/Code_Overview.html) 的“Adding new kinematics”明确要求：

- 在 `klippy/kinematics/` 实现运动学类；
- 必要时在 `klippy/chelper/` 实现 C 的步进位置函数；
- 实现 `calc_position()`，由步进位置反算工具头坐标；
- 处理 `check_move()`、`home()`、`set_position()` 等；
- 用专门 G-code 和测试覆盖关键运动与回归。

因此，剪刀 Klipper 路线不是改一行配置，而是进入主机 Python＋C 辅助运动学、回零和测试。论坛中的提问只能证明有人有同样需求，不能证明 Klipper 已原生支持任意非线性轴。[Klipper 非线性 Z 讨论](https://klipper.discourse.group/t/non-linear-z-axis-e-g-scissor-lift-mechanism/8330)

### 4. PositronConfig：折叠但保留原运动学的对照

上游：`Positron3D/PositronConfig`，快照目录 `external/positron-config/`。

它适合作为“机器可折叠，但打印时仍按既有线性轴工作”的对照。重点看回零、轴方向、限位和校准，而不是寻找并不存在的剪刀运动学。

### 5. FullControl：路径与 G-code 生成基础

上游：`FullControlXYZ/fullcontrol`，快照目录 `external/fullcontrol/`。

它适合学习从几何路径生成可控 G-code，但普通线性折叠机构不需要重写切片。只有在改变打印方向、非平面路径或折叠过程中参与打印时，才进入更复杂的路径生成。

### 6. Open5x 与 Fractal Cortex：五轴路线的真实算法门槛

- [Open5x 论文](https://arxiv.org/html/2202.11426v2)与[代码](https://github.com/FreddieHong19/Open5x)：包含正逆运动学、保形切片和 G-code 生成；适合评估五轴，而不是给折叠首版增加功能。
- [Fractal Cortex](https://github.com/FractalRobotics/Fractal-Cortex)：多方向五轴切片，将模型分成子体积并沿不同方向切片；同样属于后续独立路线。

## 四、算法验证必须先于实机连续打印

### 几何模型

- 正逆映射在允许范围内是否单调；
- `H(S)` 与 `S(H)` 往返是否恢复原值；
- 折平、最低打印高度和最高高度处是否出现奇异或超范围；
- 实际偏置、杆长和驱动方向是否进入模型。

### 实机测量

- 在多个高度指令下记录真实高度，不只测一个点；
- 记录左右两侧高度差和回差；
- 比较最低与最高打印区域的电机电流、失步和速度；
- 重复执行“折叠→展开→回零→测高”，观察误差是否累积；
- 最后才进行同一文件的重复打印。

### 不应使用的 shortcut

- 用一个固定 `steps/mm` 覆盖整个剪刀行程；
- 用自动调平掩盖龙门不方正或回零漂移；
- 用摄像头／AI 代替机械基准和运动学验证；
- 在五轴代码尚未跑通前，把它写成第一版必备功能。

## 五、对技术路线的实际建议

先以“铰链／伸缩结构折叠，展开后保留线性轴”为主线，把算法工作集中在：

1. 展开与锁紧状态确认；
2. 固定机械基准上的回零；
3. 折叠前后的坐标和床面校准；
4. 未锁紧、未展开或运输状态下的运动禁止；
5. 多次折叠后的重复定位与打印验证。

如果这条路线无法形成机械差异，再评估剪刀轴；如果未来明确转向五轴，再单独进入 Open5x／Fractal 的正逆运动学与切片体系。
