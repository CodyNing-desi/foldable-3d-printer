# 可折叠 3D 打印机下一轮工作部署

**目标：** 用一台具体实机完成“基线打印→折叠→收纳→展开锁紧→回零→恢复打印”的第一轮机器验证。

**依据：** `docs/planning/技术规划.md`、`docs/research/算法基础与技术路线.md`、`teacher_feedback/老师点评_整理.md`。

**主线：** 铰链折叠＋独立机械基准＋两点锁紧；展开后保留原线性运动学。剪刀轴、五轴和自动展开不阻塞本轮交付。

## 一、采用成熟开源项目的工作方式

| 参考项目 | 直接借用的做法 | 本轮落地 |
|---|---|---|
| Positron / PositronConfig | 机械文件、机器配置、专用校准测试分开；变更持续记录 | `design/`、`software/`、`experiments/` 分开；每次折叠机构改动记录版本 |
| Klipper | 运动学、回零、配置和测试有明确边界；自定义运动学必须有测试 | 首版不改运动学；先备份原配置，再验证回零、锁紧状态和运动禁止 |
| FullControl | 路径先生成和预览，再交给机器；提供最小教程与示例 | 所有测试 G-code 先检查／预览；固定一个最小测试文件，不在中途换件 |
| Open5x | 论文、硬件、BOM、设置、代码和演示形成同一条证据链 | 每项结构判断都对应 CAD／照片／测试记录，不只放渲染图 |
| Fractal Cortex | 公开已知问题；保留三轴模式作对照；把用户需求映射到设计决策 | 保留原机作对照；维护失败与限制清单，不宣称未验证的可靠性 |
| FoldaRap | 标准件优先、版本迭代、真实携带和打印测试 | 先复用实机与标准铰链／紧固件；每轮样机都做一次真实展开打印 |

## 二、新一轮文件纪律

上游快照 `external/` 保持只读，不在其中改自己的设计。

```text
design/                 自己绘制的状态图、机构图和 CAD
hardware/               BOM、接线、接口与实机测量
software/               原配置备份、当前配置、G-code 与脚本
experiments/
  01_baseline/          未改装机器的基线
  02_fold_cycle/        折叠展开循环
  03_redeploy/          展开后的回零与定位
  04_print_proof/       恢复打印与三次重复
docs/                   规划、报告和评审材料
external/               上游项目快照，不修改
```

每个实验目录至少包含：日期、机器、机构版本、配置文件版本、操作步骤、原始测量、失败现象和对应照片／视频。没有原始记录的结果不进入结论。

## 三、角色与责任

- **结构负责人**：折叠转轴、机械基准、锁紧、碰撞与收纳。
- **电控负责人**：控制器、限位、到位／锁紧状态、加热与运动安全。
- **算法负责人**：原配置备份、状态流程、回零、测试 G-code 与数据检查。
- **验证与文档负责人**：实验表、照片视频、竞品对照、失败记录和评审材料。

每人不只交“负责部分的图”，还要交一个可核验的输出。跨线接口以同一份接口表为准。

## 四、按顺序执行

### 任务 1：冻结实机与原机基线

**负责：** 验证与文档负责人主记录，算法负责人备份配置，结构负责人测量。

- [ ] 确认本轮实际使用的机器，不写“某通用机型”代替。
- [ ] 备份当前机器配置、切片配置和测试 G-code 到 `software/baseline/`。
- [ ] 测量龙门、杆件、床、工具头、线缆、料卷和附件的位置与运动包络，存入 `hardware/实机测量.md`。
- [ ] 用原机打印固定测试件，将用时、结果和照片放入 `experiments/01_baseline/`。
- [ ] 明确老师指出的杆件是哪一个，以及它为何阻挡折叠。

**验收：** 同一台机器有配置备份、尺寸、原机打印结果和明确的首要结构阻挡；缺任一项就不进入折叠设计。

### 任务 2：完成两种状态的机构定义

**负责：** 结构负责人，算法与电控负责人检查运动和状态边界。

- [ ] 在 `design/` 画打印状态和收纳状态，标出共同零件、转轴、基准面、两个锁紧点及附件位置。
- [ ] 画出完整转动轨迹，标出床、丝杆、工具头、线缆和料卷的碰撞区。
- [ ] 写清折叠／展开顺序，以及哪些零件需要拆卸。
- [ ] 对照 Positron、FoldaRap、Elka1、Nomad，写出一项机器层面的具体差异和对应验证方法。

**验收：** 另一人能仅凭两张状态图和操作顺序完成动作复述；不存在尚未解释的杆件或附件阻挡。

### 任务 3：制作关键机构，而不是先做完整外壳

**负责：** 结构负责人。

- [ ] 制作包含真实转轴、基准面和锁紧点的 1:1 关键样机，文件进入 `design/prototype_v1/`。
- [ ] 先低速手动完成一次折叠与展开，记录所有干涉。
- [ ] 修正后再进行 20 次循环，数据进入 `experiments/02_fold_cycle/log.csv`。
- [ ] 记录卡滞、碰撞、松脱、零件变形和锁紧失败，不只记录成功次数。

**验收：** 20 次循环有完整原始记录；样机展开后能被两点锁紧，且无需手扶保持工作位置。若失败，先修机构，不做自动展开。

### 任务 4：建立展开后的安全与状态检查

**负责：** 电控负责人和算法负责人。

- [ ] 在 `hardware/接口表.csv` 写清到位信号、锁紧信号、回零信号和原机运动／加热接口。
- [ ] 在 `software/` 保存与原配置的差异，不覆盖 baseline。
- [ ] 验证未展开或未锁紧时不能进入正常打印流程。
- [ ] 从固定机械基准执行回零，记录结果；不通过修改非线性运动学来掩盖机构问题。

**验收：** 锁定前后状态可区分；回零开关不安装在折叠时会受力移位的零件上；异常状态能阻止运动。

### 任务 5：验证折叠后的恢复能力

**负责：** 算法负责人和验证负责人。

- [ ] 每次展开后测量龙门方正、基准位置和 Z 回零差异，存入 `experiments/03_redeploy/`。
- [ ] 记录是否需要重新调平及调平时间。
- [ ] 参考 Positron 的专用校准件思路，设计一个能同时检查中心与边缘的床面测试，而不是只看喷嘴某一点。
- [ ] 在 `experiments/04_print_proof/` 使用与基线相同的 G-code 再打印。

**验收：** 原机与折叠后的结果可以按同一指标比较；任何重新调平都计入展开成本。

### 任务 6：形成下一轮评审证据包

**负责：** 验证与文档负责人，三名技术负责人各自确认自己的内容。

- [ ] 汇总折叠前后尺寸、展开时间、工具数量、循环记录、回零差异与打印结果。
- [ ] 保留至少一段不剪切的折叠→展开→回零→打印视频。
- [ ] 更新 BOM、机构风险、失败清单和下一步，不删除失败记录。
- [ ] 将“已有项目已经做到什么”与“本组实际多做了什么”分成两栏。
- [ ] 把本组实测证据映射到课程提交③／④的对应页面。

**验收：** 评审者能从一份测试件反查到机器版本、配置、操作过程和打印结果；所有创新点都有机器层面的验证，而不是后台功能描述。

## 五、下一轮结束条件

下一轮工作只有满足以下条件才算结束：

1. 实机、首要结构阻挡和折叠对象明确；
2. 主路线关键机构能实际折叠、展开和两点锁紧；
3. 有原机基线和至少一次折叠后的恢复打印；
4. 有真实失败记录和下一轮修改依据；
5. 五轴、剪刀非线性和自动展开均未抢占主线时间。

如果只能完成收纳包装，不能恢复打印，本轮就不能宣称折叠机器成立。

## 六、后续独立队列

以下事项只有在主线验收后才重新估算：

- 按钮／电机自动展开；
- 剪刀 Z 轴的非线性运动学与驱动；
- 五轴逆运动学、姿态与切片；
- 长尺寸打印；
- 折叠动作直接参与打印过程。

它们进入独立研究任务，不写入本轮必须交付的清单。
